# 用户登录与鉴权流程

> 代码参考：day12 / day13

三端同一套路，差别只在账号字段和用户表：

| 端 | 登录接口 | 查库条件 | 用户表 |
| --- | --- | --- | --- |
| APP | `POST /api/v1/login/login_auth` | phone | `ap_user` |
| 自媒体 | `POST /login/in` | name | `wm_user` |
| 管理端 | `POST /login/in` | name | `ad_user` |

---

## 总流程

```text
① 登录：校验账号密码 → 签发 JWT(token) 返回前端
② 后续请求：Header 带 token
③ 网关：验 token 是否有效 → 解析出 id → 写入 Header: userId
④ 微服务拦截器：读 userId → 放进 ThreadLocal
⑤ 业务：从 ThreadLocal 取当前用户，决定是否允许操作
```

---

## 1. 登录流程（以 APP 为例）

入口：`ApUserLoginController` → `ApUserServiceImpl#login`

### 1.1 正常登录（手机号 + 密码都传了）

```text
1. 判断 phone、password 都不为空
2. 按 phone 查 ap_user
   - 查不到 → 返回「用户不存在」
3. 取出库里的 salt、password
4. 用前端明文密码做同样加密：md5(明文密码 + salt)
5. 和库里的 password 字符串 equals 比对
   - 不一致 → 返回「密码错误」
6. 签发 JWT：AppJwtUtil.getToken(用户id)
   - claims 里只放 id
7. 返回 { token, user }
   - user 里 salt、password 先清空再返回，避免泄露
```

关键代码：

```java
ApUser dbUser = getOne(Wrappers.<ApUser>lambdaQuery().eq(ApUser::getPhone, dto.getPhone()));
if (dbUser == null) {
    return ResponseResult.errorResult(..., "用户信息不存在");
}

String pswd = DigestUtils.md5DigestAsHex((dto.getPassword() + dbUser.getSalt()).getBytes());
if (!pswd.equals(dbUser.getPassword())) {
    return ResponseResult.errorResult(AppHttpCodeEnum.LOGIN_PASSWORD_ERROR);
}

map.put("token", AppJwtUtil.getToken(dbUser.getId().longValue()));
dbUser.setSalt("");
dbUser.setPassword("");
map.put("user", dbUser);
```

密码为什么这么比：注册时存的就是 `md5(明文+盐)`，登录用同一算法再算一遍，和库里密文比，不存明文。

### 1.2 游客登录（phone 或 password 为空）

```text
1. 不查库、不验密码
2. 直接 AppJwtUtil.getToken(0L)  // id 约定为 0 = 游客
3. 只返回 token，没有 user
```

自媒体 / 管理端：**没有游客**；name、password 为空直接参数错误，否则按 name 查库，盐密码比对同上。

## 2. 网关鉴权流程：`AuthorizeFilter`

三套网关逻辑一样（app / wemedia / admin）。

```text
1. 取当前请求 path
2. path 包含 "/login" → 直接放行（登录本身不要求 token）
3. 从 Header 取 token
   - 为空 → 401
4. AppJwtUtil.getClaimsBody(token) 解析
5. AppJwtUtil.verifyToken(claims) 判断是否过期/无效
   - 返回 1 或 2 → 401
6. 从 claims 取出 id
7. 写入下游请求头：userId = id
8. 放行到微服务
```

关键代码：

```java
if (request.getURI().getPath().contains("/login")) {
    return chain.filter(exchange); // 登录放行
}

String token = request.getHeaders().getFirst("token");
if (StringUtils.isBlank(token)) {
    response.setStatusCode(HttpStatus.UNAUTHORIZED);
    return response.setComplete();
}

Claims claimsBody = AppJwtUtil.getClaimsBody(token);
int result = AppJwtUtil.verifyToken(claimsBody);
if (result == 1 || result == 2) {
    response.setStatusCode(HttpStatus.UNAUTHORIZED);
    return response.setComplete();
}

Object userId = claimsBody.get("id");
request.mutate().headers(h -> h.add("userId", userId + "")).build();
```

要点：网关验完 JWT 后，下游**不再解析 token**，只认 `userId` 头。

## 3. 微服务身份传递：Interceptor → ThreadLocal

```text
1. 拦截器 preHandle：读 Header userId
2. 有值 → new 一个用户对象，只 setId(userId)，塞进 ThreadLocal
3. Controller / Service 里 XxxThreadLocalUtil.getUser() 取当前用户
4. afterCompletion：ThreadLocal.clear()，防止线程复用脏数据
```

```java
// AppTokenInterceptor（自媒体是 WmTokenInterceptor + WmThreadLocalUtil）
String userId = request.getHeader("userId");
if (userId != null) {
    ApUser apUser = new ApUser();
    apUser.setId(Integer.valueOf(userId));
    AppThreadLocalUtil.setUser(apUser);
}
```

业务使用：

```java
ApUser user = AppThreadLocalUtil.getUser();
if (user == null) {
    return ResponseResult.errorResult(AppHttpCodeEnum.NEED_LOGIN);
}
// 写操作还可再判断 user.getId()==0 → 游客不允许
```

## 串起来看一次完整请求

```text
登录：phone+password → 查用户 → md5(密码+salt) 比对 → 返回 token
  ↓
点赞/评论等：Header: token=xxx
  ↓
网关：token 有效？→ 写出 userId=4
  ↓
拦截器：ThreadLocal 放入 ApUser(id=4)
  ↓
Service：getUser() 拿到当前用户，继续业务
```
