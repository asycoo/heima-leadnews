## 1. 模块概览

| 项 | 说明 |
| --- | --- |
| 服务模块 | `heima-leadnews-service/heima-leadnews-comment` |
| 启动类 | `CommentApplication`（端口 `51806`，服务名 `leadnews-comment`） |
| 存储 | MongoDB 库 `leadnews-comment`（排除 JDBC 自动配置） |
| 注册中心 | Nacos |
| 依赖调用 | Feign：`IUserClient`（查用户）、`IArticleClient`（查文章评论开关） |
| 消息 | Kafka：发表评论后发送热点文章分数更新消息 |

### 核心类结构

```
heima-leadnews-comment
├── controller/v1
│   ├── CommentController          # 评论：保存 / 点赞 / 列表
│   └── CommentRepayController     # 回复：保存 / 点赞 / 列表
├── service / service/impl
│   ├── CommentServiceImpl
│   └── CommentRepayServiceImpl
├── pojos                          # Mongo 文档 + VO

heima-leadnews-model/.../comment/dtos
├── CommentSaveDto / CommentLikeDto / CommentDto
└── CommentRepaySaveDto / CommentRepayLikeDto / CommentRepayDto
```

## 2. MongoDB 集合

| 集合名 | 实体 | 用途 |
| --- | --- | --- |
| `ap_comment` | `ApComment` | 文章评论 |
| `ap_comment_like` | `ApCommentLike` | 用户对评论的点赞记录 |
| `ap_comment_repay` | `ApCommentRepay` | 评论回复 |
| `ap_comment_repay_like` | `ApCommentRepayLike` | 用户对回复的点赞记录 |

### 2.1 ApComment 关键字段

| 字段 | 含义 |
| --- | --- |
| `authorId` / `authorName` / `image` | 评论人信息 |
| `entryId` | 文章 id |
| `content` | 评论内容 |
| `likes` / `reply` | 点赞数 / 回复数 |
| `type` | 0=文章，1=动态 |
| `flag` | 评论标记（普通/热点/置顶等） |
| `createdTime` | 创建时间（列表按此倒序） |

### 2.2 ApCommentRepay 关键字段

| 字段 | 含义 |
| --- | --- |
| `commentId` | 所属评论 id |
| `authorId` / `authorName` | 回复人 |
| `content` | 回复内容 |
| `likes` | 点赞数 |
| `createdTime` | 创建时间 |

## 3. 需求对照实现

### 3.1 发布评论

| 需求 | 代码实现 |
| --- | --- |
| 文章详情发表评论 | `POST /api/v1/comment/save` → `CommentServiceImpl.saveComment` |
| 必须登录 | `AppThreadLocalUtil.getUser()` 为空则 `NEED_LOGIN` |
| 内容不超过 140 字 | `content.length() > 140` 校验 |
| 文本垃圾检测 | **未实现**，代码注释：`//3.安全检查 自行实现` |
| （额外）文章评论开关 | Feign 查 `ApArticleConfig.isComment`，关闭则拒绝 |
| （额外）热点分 | 保存成功后 Kafka 发 `UpdateArticleMess`（COMMENT +1） |

**入参** `CommentSaveDto`：`articleId`、`content`

**流程简述**：参数校验 → 文章可评论校验 → 140 字 → 登录 →（安全检查预留）→ Feign 查用户 → 写入 `ap_comment` → Kafka → 成功

---

### 3.2 评论点赞 / 取消点赞

| 需求 | 代码实现 |
| --- | --- |
| 点赞：数量 +1，并记录用户点赞 | `operation == 0`：`likes+1`，写入 `ap_comment_like` |
| 取消：数量 -1，更新点赞数据 | 否则：`likes` 减一（不低于 0），删除 `ap_comment_like` |
| 必须登录 | 未登录返回 `NEED_LOGIN` |

**接口**：`POST /api/v1/comment/like`  
**入参** `CommentLikeDto`：`commentId`、`operation`（0 点赞 / 1 取消）  
**返回**：`{ "likes": 当前点赞数 }`

---

### 3.3 评论列表

| 需求 | 代码实现 |
| --- | --- |
| 展示内容、作者、点赞数、回复数、时间 | 返回 `ApComment` / `CommentVo` 字段 |
| 按文章检索、创建时间倒序 | `entryId = articleId`，`createdTime` DESC |
| 分页默认 10 条 | `limit(10)`；条件 `createdTime < minDate`（时间游标分页） |
| 当前用户已点赞则高亮 | 已登录时查 `ap_comment_like`，命中则 `CommentVo.operation = 0` |

**接口**：`POST /api/v1/comment/load`  
**入参** `CommentDto`：`articleId`、`minDate`、`index`  
**说明**：未登录直接返回评论列表；已登录包装为 `CommentVo`（含 `operation`）

---

### 3.4 评论回复 - 发布

| 需求 | 代码实现 |
| --- | --- |
| 与发表评论一致（登录、140 字、垃圾检测） | 登录 + 140 字已做；垃圾检测同样预留未实现 |
| 保存成功更新评论回复数 | `ApComment.reply + 1` 后 `save` |

**接口**：`POST /api/v1/comment_repay/save`  
**入参** `CommentRepaySaveDto`：`commentId`、`content`

---

### 3.5 回复点赞

与评论点赞一致：`POST /api/v1/comment_repay/like`  
操作集合：`ap_comment_repay` + `ap_comment_repay_like`  
入参：`commentRepayId`、`operation`

---

### 3.6 回复列表

| 需求 | 代码实现 |
| --- | --- |
| 与评论列表一致 | 按 `commentId` 查，`createdTime` 倒序 |
| 分页 | 代码写死 `size = 20`（DTO 有 `size` 字段但未使用） |
| 点赞高亮 | 已登录时 `CommentRepayVo.operation = 0` |

**接口**：`POST /api/v1/comment_repay/load`

## 5. 登录与拦截

1. 网关鉴权后把用户 id 放进请求头 `userId`
2. `AppTokenInterceptor` 读取 `userId`，构造 `ApUser` 放入 `AppThreadLocalUtil`
3. Service 通过 ThreadLocal 判断是否登录；发评论/点赞强制登录，列表可不登录

## 7. 实现时注意点

1. **垃圾检测**：`saveComment` / `saveCommentRepay` 已调用 `GreenTextScan`；`bootstrap.yml` 需配置 `aliyun.accessKeyId/secret`。
2. **回复列表 size**：DTO 有 `size`，实现写死 20，与评论列表默认 10、接口文档不完全一致，联调时注意。
3. **分页方式**：不是传统 page/size，而是 `minDate` 时间游标（查比该时间更早的下一批）。
4. **自媒体评论管理**：`wemedia` 中另有 `CommentManageController`（同一 Mongo 库），属于运营/自媒体侧管理，不在本需求「APP 文章评论」主流程内。
)
